Customize only the new copy. The percentages remove intentionally random delivery failures from this correctness demonstration. They do not make delivery infallible when networking, binding, queuing or receipt processing fails.

```bash
python3 - <<'PY'
from pathlib import Path
import re
import secrets

root = Path('/opt/smppsim-lyca')
path = root / 'conf/smppsim.props'
password_file = root / 'bind-password'
if password_file.exists():
    raise SystemExit('Lyca was already prepared. Reuse its existing configuration and password.')
password = secrets.token_hex(4)
updates = {
    'SMPP_PORT': '2775',
    'HTTP_PORT': '89',
    'SMPP_CONNECTION_HANDLERS': '10',
    'CONNECTION_HANDLER_CLASS': 'com.seleniumsoftware.SMPPSim.StandardConnectionHandler',
    'PROTOCOL_HANDLER_CLASS': 'com.seleniumsoftware.SMPPSim.StandardProtocolHandler',
    'LIFE_CYCLE_MANAGER': 'com.seleniumsoftware.SMPPSim.LifeCycleManager',
    'SYSTEM_IDS': 'jasmin_lyca',
    'PASSWORDS': password,
    'MESSAGE_STATE_CHECK_FREQUENCY': '1000',
    'MAX_TIME_ENROUTE': '10000',
    'DELAY_DELIVERY_RECEIPTS_BY': '1000',
    'PERCENTAGE_THAT_TRANSITION': '100',
    'PERCENTAGE_DELIVERED': '100',
    'PERCENTAGE_UNDELIVERABLE': '0',
    'PERCENTAGE_ACCEPTED': '0',
    'PERCENTAGE_REJECTED': '0',
    'UNDELIVERABLE_PHONE_NUMBERS': '',
    'LOOPBACK': 'FALSE',
    'DELIVERY_MESSAGES_PER_MINUTE': '0',
    'OUTBIND_ENABLED': 'false',
    'CALLBACK': 'false',
    'SMSCID': 'LycaLab',
}
text = path.read_text()
for key, value in updates.items():
    pattern = re.compile(r'^\s*' + re.escape(key) + r'\s*=.*$', re.M)
    if pattern.search(text):
        text = pattern.sub(lambda match: key + '=' + value, text)
    else:
        text = text.rstrip() + '\n' + key + '=' + value + '\n'
path.write_text(text)
path.chmod(0o644)
password_file.write_text(password + '\n')
password_file.chmod(0o600)
print('Prepared:', path)
print('Username: jasmin_lyca')
print('Password file:', password_file)
PY
```

## 5. Create the Lyca destination filter in Joyce

Click **Filters → Add** and enter:

| Field | Value |
|---|---|
| FID | `mt_lyca` |
| Nature | `ALL` |
| Filter type | `DestinationAddrFilter` |
| Parameter Key | `destination_addr` |
| Parameter Value | `^256726[0-9]{6}$` |

Save. The expression requires `256726` followed by exactly six digits. `256726123456` matches; `256771234567`, `256701234567` and `254722123456` do not.

Choose **ALL** in the filter form: this Joyce build puts shared filters such as `DestinationAddrFilter` under ALL, while its MT category contains user/group filters. Attaching the shared destination filter to the MT route below makes it govern outbound messages.

This filter is stored in Joyce until attached to a route. A standalone filter ID does not have to appear in jCLI's independent filter catalogue for the route to work; the PB API stores the actual filter object on the route.

## 7. Add the separate Comms application price

Joyce edits Jasmin's upstream rate. Comms uses its own SQLite `rates` table for quoting, reserving and settling customer test credits. These are different balances/transactions, even if both demo prices are `1.00`.

In the supplied Comms implementation, `PRICING_JSON` only seeds an empty rate table. Changing it and restarting does not insert a new carrier into an existing database. The existing admin rate endpoint changes a price but does not create a new prefix rule.

Download `add_lyca_rate.py` and place it on the **Jasmin/Comms host**, e.g. `/root/add_lyca_rate.py`. It uses the Python standard library and does not need application packages.

Confirm the actual database path used by the running Comms API and worker. The previously confirmed path is:

```text
/root/loadtesting/jasmin-comms-lab/backend/data/comms.sqlite3
```

For a containerized Comms deployment use the actual **host-mounted database path**, not a container-only `/data` path or an old unused database. The script refuses to create a missing database.

First preview the addition, replacing `smppc_1_5` with the exact CID from Joyce:

```bash
python3 /root/add_lyca_rate.py \
  --database /root/loadtesting/jasmin-comms-lab/backend/data/comms.sqlite3 \
  --connector smppc_1_5 --price 1.00
```

Check the printed path, pattern, connector and price. The internal SQLite integer `unit_price: 100` represents **1.00** test credit. The helper places this specific application prefix ahead of existing broad rules.

Apply the same reviewed values:

```bash
python3 /root/add_lyca_rate.py \
  --database /root/loadtesting/jasmin-comms-lab/backend/data/comms.sqlite3 \
  --connector smppc_1_5 --price 1.00 --apply
```

Before insertion the helper makes an online SQLite backup under `lyca-rate-backups/` beside the database. It adds only the new rate and an administrative event. Wallets, messages and jobs are not altered. An identical existing rate is a no-op; a conflicting existing rule is refused rather than overwritten.

Refresh Comms and inspect Rates/Admin Rates. The frontend obtains the list from `/api/rates`, so a new backend rate does not require a React rebuild. New campaign quotes read current database rates; existing campaigns retain their captured prices.

For future **fresh database** installations, also add the matching Lyca object to the configured seed list without removing the existing entries:

```json
{"name":"Lyca lab","pattern":"^256726[0-9]{6}$","unit_price":"1.00","connector":"THE_ACTUAL_JOYCE_CID"}
```

This JSON object is an entry to merge into `PRICING_JSON`, not the entire replacement list. Do not source a JSON-containing `.env` as a shell script.
